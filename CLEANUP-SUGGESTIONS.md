# Repository cleanup – what to delete / ignore before push

## Summary

Your project had **no `.gitignore`**, so Git was able to track (or would track) build artifacts and dependencies. That makes the repo very large and slow to push. A proper **`.gitignore`** has been added so these are never committed.

---

## 1. Do NOT commit (now ignored via `.gitignore`)

| Path | Why |
|------|-----|
| **`node_modules/`** | Dependencies (~8700+ files). Recreated with `pnpm install`. Never commit. |
| **`.next/`** | Next.js build cache and output (~140+ files, webpack cache). Recreated with `pnpm run build` or `pnpm dev`. Never commit. |
| **`.env.local`** | Local environment variables (often secrets). Never commit. |
| **`next-env.d.ts`** | Auto-generated by Next.js. Recreated on build. |
| **`out/`** | Next.js static export output (if you use `next export`). Regenerated. |
| **`*.log`** | Debug logs. Not needed in repo. |

---

## 2. Safe to delete from disk (optional – to free space only)

You can delete these **locally** to save disk space. They are recreated when needed:

- **`.next/`** – Delete anytime. Regenerated by `pnpm dev` or `pnpm run build`.
- **`node_modules/`** – Delete if you want a clean slate. Regenerated by `pnpm install`.

Do **not** delete these if you’re actively developing; only if you’re cleaning disk. Do **not** commit them before deleting; the new `.gitignore` already prevents that.

---

## 3. Keep and commit

- **`pnpm-lock.yaml`** – Keep and commit so installs are reproducible.
- **`.env.example`** – Keep and commit as a template (no real secrets).
- **`src/`**, **`scripts/`**, **`postgres-schema.sql`**, **`package.json`**, **`tsconfig.json`**, **`next.config.mjs`**, **`middleware.ts`**, etc. – All source and config. Commit as usual.

---

## 4. If you already committed `node_modules` or `.next` in the past

If those folders were added in a previous commit:

1. Remove them from the index (keeps files on disk):  
   `git rm -r --cached node_modules`  
   `git rm -r --cached .next`
2. Commit the change.
3. The new `.gitignore` will keep them from being added again.

---

## 5. After adding `.gitignore`

1. Run: `git status`
2. You should **not** see `node_modules/` or `.next/` as untracked.
3. Add and commit as usual; only source and config will be tracked, so the repo stays small and pushable.
